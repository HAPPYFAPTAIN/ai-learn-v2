## 当前接口与迁移

- `POST /projects/{id}/notes`、`POST /cards` 接受可选 UUID `requestId`。新前端始终发送；旧客户端不发送仍兼容，但不具备重放保护。同一编号与相同输入返回原始 201 结果，内容不同返回 409 CONFLICT；相同内容使用不同编号允许有意创建两份。
- 前端在当前编辑会话内保留同一输入的编号，结果未知后的明确重试沿用；确认成功或明确丢弃后结束该操作。不自动重放写请求，不把草稿/编号持久化到浏览器。刷新后需要重新核对记录。
- 回执按账号/操作隔离，强制 RLS，内容摘要和原始响应与业务记录原子保存。回执不自动过期，保留至账号删除；删除原记录/章节/项目时清除回执正文，保留编号与摘要墓碑，避免旧请求重新创建已删除内容。该策略增加数据库存储，不表示无需容量评估。
- `GET /projects/{id}/reports`：默认 30 个不同日期，`limit` 范围 1–366，`offset>=0`，可选 `fromDate/toDate`（含首尾日期）；起始晚于结束返回 422。前端继续聚合已加载日报，尚未增加遍历全部历史的界面。
- 日报 `date` 是北京时间业务日期；数据库 report_date 的 UTC 零点编码仅用于日期键。学习事件和 FSRS 时间戳仍存 UTC。旧 UTC 日界的历史快照不会被静默重算；需要统一历史口径时应在备份后另行按学习事件重建。
- 新增迁移 `0007_creation_receipts`，含回执表、授权/RLS 和日报查询索引。必须先迁移再运行新代码。历史 0001/0002 会读取当前元数据，新迁移兼容空库已提前建表的情况；没有修改历史迁移。回退会删除回执，正式回退前需评估幂等历史丢失的影响。
- OpenAPI 与 TypeScript 类型已重新生成；没有增加模型请求、worker 并发、运行依赖或修改固定的 kotaemon 源码。
