## 为后续架构保留的基础

- React 静态前端、OpenAPI 类型和 `/api/v2` 契约；不嵌入旧 Gradio 回调。
- 官网身份 → tenant 映射、Postgres/RLS 与按租户文件存储；人数少也不共享个人数据。
- 统一网关、主模型选择、官网用户身份和调用事件编号。
- Procrastinate + `job_progress` 持久化任务；模型等待不占业务数据库连接。新问答先保存不可变输入，恢复时复用同一请求与事件。
- 原件、检索块、向量分开管理；删除索引与原件清理由事务和持久化队列协调，避免删除后重建旧索引。
- 首次路线耗时参考 45 秒，之后用本账号同模型近期成功中位值；百分比是估算，排队不承诺剩余时间，保存成功才到 100%。不再调用一次模型来估算模型耗时。

## 登录适配与上线前条件

新版 API 已按现有官网 `GET .../learn-everything/authorize`、204 + `X-Learn-User` 协议适配 `learn_entry`。要求可信代理密钥、预期账号、同源写入，转发官网续期 Cookie；不信任客户端提供的用户身份。默认未配置可信入口时拒绝使用。详见 `official-auth.md`。

这只完成代码与模拟协议检查，**尚未在真实官网联调，也未部署试用站**。仍需：

1. 为 2–3 个测试账号配置入口分流/白名单、官网登录、资格与计费网关，验证换账号和续期。
2. 确认测试机器资源、磁盘、单并发/低并发 worker、共享嵌入服务；实测两人/三人上传、生成、学习、测验与复习。
3. 为新 SPA/服务完成发布包、HTTPS 路由、备份恢复、回滚和运维配置评审；生产机 7.4G 的旧配置不能直接套用规划的全量进程配置。
4. Edge/Safari 实机体验与真实模型质量/费用/时延验收。自动化截图不能代替。
