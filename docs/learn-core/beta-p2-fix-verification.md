# 小范围内测前两项 P2 修复

日期：2026-11-18。基于 `e2023ed`，只修复审查确认的两项 P2；不表示已经部署或完成在线验收。

## 修复行为

1. 删除章节前收集将被整份删除的跨章节测验所涉及的存活章节；删除测验和答题证据后，按剩余测验、复习卡与学习状态重算这些章节的掌握度。完成状态继续独立保留；整项目删除不重算即将删除的章节。
2. 创建计划接受可选 UUID `requestId`，使用已有的租户级创建回执。同账号同编号同输入返回原项目和原生成任务，不重复入队；改变输入返回 409。不同编号允许有意创建相同内容。项目、回执、进度与队列记录在同一事务中提交，失败回滚不消耗编号。
3. 首页始终发送编号。写入结果未知时保留目标、锁定输入和提交，先做只读核对；明确允许后再提交仍沿用同一编号。已保存时进入原计划并观察原任务。没有自动重放写请求。
4. `GET /api/v2/projects/creation-requests/{request_id}` 返回当前账号已提交的原始创建响应，未找到返回 200 + null。原生成状态是创建时快照，最新状态继续从 jobs 接口读取。回执受 RLS 保护；相同编号在不同账号互不影响。
5. 删除项目清空对应回执正文并保留墓碑，旧请求重放和结果查询返回 409，不恢复项目或再次生成。无需新增迁移，但运行环境必须已有 `0007_creation_receipts`。

兼容旧客户端不带编号的创建请求，这类请求仍不具备重放保护。首页编号只保留在当前页面会话内，不将学习目标/草稿写入浏览器存储；刷新、离开或重新登录后应先核对计划列表，不承诺跨刷新恢复原创建意图。原始创建响应保留至账号删除，项目删除时清除正文，需将回执存储纳入容量评估。

## PR、部署和开放内测的界限

这两项修复及提交前检查通过后，可以提功能 PR 进行审查。PR 不等于线上验收通过；可以先部署独立验收环境，达到下面三项门槛后再开放给 2–3 个受邀账号。

| P1 上线门槛 | 建议负责人 | 依赖与完成证据 |
| --- | --- | --- |
| 官网真实账号、资格、续期、切号和模型扣费链路 | 后端负责人牵头，官网鉴权/模型网关维护者配合，前端同学参与页面验收 | 提供测试域名、测试账号/额度和受控代理配置；从浏览器完成生成，核对身份、任务及计费事件；过期、无资格、切号和额度不足行为有记录 |
| 新版发布与回退 | 后端/部署负责人；有运维则由运维协作，前端提供生产构建 | 补齐新版发布清单、SPA 子路径、API/SSE 代理、API/worker/嵌入/回收进程、数据库迁移、文件权限；独立数据库和文件备份能恢复，测试账号分流可撤销 |
| 目标机器真实并发与资源 | 后端负责人牵头，前端同学和内测账号参与 | 首轮模型任务并发 1、IO 并发 1；两三人同时上传和生成，记录排队/总耗时、错误、CPU/RSS/磁盘与实际额度；重启 worker 验证恢复，无跨账号数据可见 |

这些是环境与协作条件尚未具备的验收工作，不是后端永久无法验证的问题，也不能全部交给前端。没有测试机器、官网接入和测试额度时，本地模拟无法替代这些证据。小范围内测不要求先实现原规划全部 50–200 人功能，但不能跳过身份/计费、可部署性和实际资源验收。具体操作顺序继续参考 `online-beta-handoff.md`。
