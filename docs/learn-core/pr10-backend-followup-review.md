## Standards

### S1 · P2 · 暂时断网会永久关闭任务观察

- 位置：PR `learn_web/src/api/client.ts:163`、`:175` 与 `learn_web/src/api/jobs.ts:52`、`:58`。
- 新版客户端把网络错误、等待超时包装为 `ApiError(status=0, retryable=false)`。原有任务轮询遇到这种错误会调用 fail 并关闭 SSE/轮询，因此短暂离线也会永久结束观察。后端任务可能仍在正常索引/生成；批量上传会显示“索引待确认”，停止下一份。
- 证据：新增两个临时回归分别覆盖首次观察 GET 离线、SSE 断开后的兜底 GET 离线；相同场景在旧客户端通过，在 PR 客户端均失败。PR 原有 4 项 jobs 单测仍通过，说明原测试没有覆盖此组合。
- 责任：前端。区分只读状态观察的可恢复传输错误和写请求的结果未知；保留 GET 重连，但不要自动重放创建/计费操作。后端不应为了迎合错误分类而篡改任务状态或返回假成功。

### S2 · P2 · 批量删除未覆盖新的网络错误类型

- 位置：PR `learn_web/src/components/MaterialBatchActions.tsx:129`。
- 交接文档明确“遇到网络问题、限流或服务错误时停止后续请求”（PR `frontend-backend-handoff.md:106`）。代码仅在非 ApiError、429、5xx 时停止；新版网络错误已变成 status=0 的 ApiError，落不到任何停止分支，于是后续文件仍会被请求删除。
- 证据：静态核对错误构造与实际分支；此项未做 DOM/真实断网浏览器复现，不将它写成已跑过浏览器回归。
- 责任：前端。停止条件覆盖网络/超时和结果未知；后端继续保持重复删除成功或 404，并执行真实归属检查。复测用首份 DELETE 已提交但响应丢失，以及传输层失败，不能只模拟 HTTP 500。

未发现 XHR 上传新增 Cookie/预期账号头绕过，PDF 原件也复用鉴权下载接口。没有另报仅基于代码异味的重构事项。

### B2 · P2 · 笔记/批注/手动卡片缺创建幂等

- PR `frontend-backend-handoff.md:173` 明确要求后端后续提供创建请求编号，重复相同编号返回原结果，不同内容冲突。当前 `NoteCreate`、`CardCreate` 均无请求编号并禁止额外字段。
- 真实测试库：相同笔记请求两次均 201、返回两个不同 id；卡片同样产生两份。额外传 requestId 均 422。此观察不表示相同内容的两次有意创建应合并，而是当前没有标识“同一次操作重放”的契约。
- PR 的“先读列表再由用户重试”能降低误操作，但不能解决旧请求延迟提交、查询未见最新提交、多标签页同文记录等不确定性。这是明确记录的后端能力缺口，不是 PR 承诺已经实现的去重。
- 责任：后端先定义按租户/操作/请求编号隔离的原子幂等记录、内容摘要、返回结果、保留周期及冲突错误，再同步生成类型和前端。不要只按正文去重，也不要仅在 Python 进程内加锁。
- 验收：同编号同内容串行/并发/响应丢失只创建一次；同编号不同内容返回明确冲突；不同账号互不影响；编辑普通内容不丢 selection。

### B3 · P2 · 同日重复日报占满列表，历史图表失真

- 后端 `learn_core/learning/reports.py:58` 每次整理创建新行，`:71` 只按日期倒序取 30 行；前端 `dashboardData.ts:11`、`reportData.ts:23` 在已经截断的列表上按日期选最大 id。
- 真实测试库先保存此前 29 天日报，再为今天整理 31 次。GET 最终返回 **30 行、只有 1 个不同日期**。其余日期尚在库中，前端已经无法绘制。当前样本包含最后一次生成记录，但仅按日期排序不保证同日版本顺序，不能依赖偶然返回顺序。
- 责任：后端先按日选择最新版本，再做日期范围/稳定排序/分页或限制；同日生成是否 upsert 需明确并发行为。前端有了按日集合后再筛选，避免重复行挤掉历史。无需新建模型聚合任务。
- 验收：重复整理同一天不减少可读取历史天数；同日最新内容稳定可见；日期范围、空日期与有记录的零值继续分开。

### B4 · P2 · “今日报告”的日界与浏览器日期不一致

- 后端 `learn_core/learning/reports.py:36` 按 UTC 的当前日期整理；PR `dashboardData.ts:9` 与 `reportData.ts:9` 使用浏览器本地日期。
- 控制时钟为 **北京时间 2026-11-18 01:00**，真实 API 整理返回日期 **2026-11-17**。数据库与 HTTP 层真实，时钟在本地探针中固定；未更改系统时间。
- 责任：共同确定业务日界，由后端按一致时区计算报告日期/区间并让前端遵守。FSRS 的 UTC 时间戳无需随日报改成无时区时间；二者是不同概念。
- 验收：北京时间 00:00 前后及 08:00 前后、浏览器跨时区、日期筛选与导出。此处是未明确统一的接口语义，不应把 UTC 存储本身列为错误。
