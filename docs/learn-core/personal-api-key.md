# 2026-11-20 问题修复及个人 API Key 接入

本文记录此前实现的个人 API Key 能力，保留用于独立本地实验。官网继续使用统一模型网关，API 和 worker 明确设置 `LEARN_MODEL_SOURCE=gateway`；代码中 personal 的默认值不是上线授权。旧 Gradio 和官网鉴权保持原样。最新线上修复、资源影响和待验项见 [online-issues-v2.md](online-issues-v2.md)。

## 逐项原因与改动

1. 配色：此前学习应用使用独立绿色主题。React 的主题变量现统一为白底青蓝色、夜间深海蓝和冰蓝强调色，保留两种主题切换；按钮文字有独立对比色。
2. 未导入 Key 的错误提示：后端过去把缺少主模型当作 `CONFLICT`，前端将所有此类错误替换为“内容已更新”。现在返回 `MODEL_NOT_CONFIGURED` 和“请先导入 API Key，并在模型设置中选择主模型”，附带导入入口。项目创建和任务入队仍在同一事务，失败不会留下半份计划。
3. 自带 DeepSeek：截图中的完整模型 ID 没有出现在源码中；正式模型页面原本读取官网网关目录，并非能据此判定为个人测试残留。个人 Key 模式现在只读取当前租户导入的供应商，不返回官网模型或自动沿用旧网关选项。保留旧数据库中的模型偏好用于回退，不删除官网共享模型及其他账号的数据。用户可明确移除自己导入的供应商和 Key。
4. 章节生成进度：原先组件只在路线生成时挂载。教材、测验、复习卡现在共用同一组件，显示阶段、估算百分比与剩余时间；依据当前账号同模型同任务类型最近十次成功耗时的中位数，没有历史时使用参考值。未保存不显示 100%，超时会说明仍在生成。重载继续跟踪同一个任务。
5. Key 输入禁用：这是此前线上网关限制的显式代码，并非浏览器故障。个人 Key 模式新增受现有官网鉴权保护的供应商接口，弹窗可提交用户 Key，服务端验证 `/models` 后按租户加密存储。选择主模型后，路线、教材、问答、测验、复习卡和润色经现有客户端调用该供应商。Key 不回显、不写浏览器存储、任务快照或用量日志。演示模式仍禁止真实 Key。

## 个人 Key 独立实验配置

独立环境安装审查过的依赖锁，按 [server-release.md](server-release.md) 的迁移角色顺序执行；不要直接用应用角色或普通 owner 跨过需要 DBA 权限的 0009。个人 Key 能力需要 `0008_model_providers`；新增表沿用现有 PostgreSQL RLS。`cryptography==46.0.2` 与旧 Linux 运行时锁中的版本相同；目标架构的 wheel 与哈希须按既有发布流程在仓库外准备。

生成一次 Fernet 密钥，保存在服务端机密管理系统或权限 `0600` 的环境文件；不得提交 Git：

```sh
python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
```

API 和 LLM worker 使用相同环境：

```dotenv
LEARN_MODEL_SOURCE=personal
LEARN_PROVIDER_ENCRYPTION_KEY=<上述生成的密钥>
```

密钥应单独备份；重启和发布时不要重新生成，否则旧 Key 无法解密。缺少配置时页面会明确提示联系管理员，并禁用导入，不回退至明文存储。官网部署必须显式设置 `LEARN_MODEL_SOURCE=gateway`；API 与 worker 必须一致。原本地代理入口也须显式选 gateway 模式，或直接使用新的个人 Key 接口。

正式页面必须经 HTTPS 访问；导入的个人 Key 会发送至应用后端，并只在供应商请求期间解密。仅支持公开 HTTPS（443）且兼容 OpenAI `/models`、`/chat/completions` 的接口。导入验证不发起付费生成；预设模型 ID 仅供参考，需在当前 Key 的真实目录中存在。Ollama、本机、内网服务和非 OpenAI 协议不支持，错误会明确说明。

## 接口与边界

- `GET /api/v2/models` 返回 `source`、`providerImportEnabled` 及该模式的模型目录。
- `GET /api/v2/model-providers` 只返回当前账号连接元信息。
- `POST /api/v2/model-providers` 接收稳定导入 `id` 和密码字段 `apiKey`；同一弹窗重试不会创建重复连接。返回验证耗时和连接元信息，不返回 Key。
- `DELETE /api/v2/model-providers/{id}` 删除当前账号连接和密钥，清空匹配的主模型偏好；已发出的供应商请求可能继续执行，未开始任务会明确失败，不能静默切换官网模型。
- `PATCH /api/v2/models/selection` 只接受当前账号目录中存在的模型。

每个账号最多 20 个供应商，每个最多 100 个模型 ID。只有明确导入时读取供应商模型目录，普通页面加载读取本地数据库。供应商地址逐次检查公网 DNS，并固定连接到已验证 IP，保留 TLS 主机验证；不跟随跳转、不使用系统代理。个人调用不向供应商发送官网内部 Key、账号标识或内部事件头。

资源影响：增加一个小型租户表与 Fernet 加解密，不增加 worker、任务并发或预生成；仍使用原有租约、任务与用量记录。进度条每秒只更新浏览器显示，不增加网络轮询或模型请求。读写超时后停止自动重复付费请求的规则保留。

## 验收

用两个不同账号确认：初始没有模型；未导入时生成会提示导入；导入后刷新仍保留；选择后实际生成使用本人供应商；对方看不到也不能移除本人的连接。分别测试白色与夜间主题、手机与桌面宽度。Key 错误不应退出官网登录。教材生成需经历排队、估算、保存、100%，刷新不新建第二次任务。

代码回归使用模拟供应商与隔离数据库，不调用真实付费模型；独立个人 Key 环境仍需使用本人 Key 完成端到端验收；不代表官网已启用个人 Key。
